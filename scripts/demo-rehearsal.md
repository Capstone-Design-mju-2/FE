# 추천 → 품절 대안 → 체험 주문 시연

## 사전 준비

1. `npm ci` 후 `npm run dev`를 실행한다. 목업 시연은 `VITE_USE_MOCK=true`로 진행한다. `.env.development.local`에 `VITE_USE_MOCK=false`가 있으면 목업이 꺼지므로, 그 줄을 지우거나 `VITE_USE_MOCK=true npm run dev`로 띄운다.
2. 브라우저에서 `/?mock=alternatives#chat`을 연다. 이 경로는 BE와 LLM 없이 고정 응답을 보여 준다.
3. **발표 직전에 한 번 미리 열어 둔다.** 개발 서버를 띄운 직후 첫 화면은 모듈 변환 때문에 수십 초 걸릴 수 있다. 미리 연 뒤에는 한 바퀴가 몇 초면 끝난다.
4. 발표 전에 아래 순서를 두 번 반복하고, 화면 공유 해상도에서도 카드와 주문 패널을 확인한다. 반복할 때는 **새 대화**를 누르거나 페이지를 새로 고친다(체험 주문 번호는 새로 고치면 `0001`부터 다시 시작한다).

## 발표 순서

| 순서 | 누를 것 | 화면에서 보여 줄 것 |
| --- | --- | --- |
| 1 | 첫 번째 예시 질문 | 추천 카드 3개. 재고 있음(내일 도착)·품절·재고 확인 불가가 한 번에 보인다 |
| 2 | 첫 카드(수분크림 A)의 **주문하기** | 주문 확인 패널. 모든 옵션이 품절로 막혀 있고 "모든 옵션이 품절이에요"가 보인다 |
| 3 | **같은 조건의 대안 보기** | "방금 품절됐어요" 안내와 새 추천. 수분크림 A가 빠지고 수분크림 C가 재고 있음(내일 도착)으로 바뀐다 |
| 4 | 수분크림 C의 **주문하기** → 옵션·수량 선택 → **주문하기** | 주문 완료. 주문 번호·옵션·수량·합계·배송 예정일과 체크 표시(그려지는 움직임이 끝날 때까지 약 1초) |
| 5 | **대화로 돌아가기** → 상단 **마이페이지** → **주문/배송 조회** 탭 | 맨 위의 "화면 체험 주문"과 방금 받은 주문 번호. 마이페이지의 첫 탭은 "내 정보"라서 탭을 한 번 눌러야 주문이 보인다 |

목업 주문은 서버에 저장되거나 재고를 차감하지 않으며 새로고침하면 사라진다.

## 리허설 기록

- 2026-11-16, 헤드리스 Chrome으로 위 순서를 자동으로 따라갔다(목업, `dev` 기준).
  - 1280×720에서 **3회 연속 통과**했다. 미리 열어 둔 뒤 한 바퀴는 약 5초였다(사람이 설명하며 누르는 시간은 제외).
  - 1920×1080과 휴대폰(390×844, 배율 3)에서도 같은 순서가 통과했고, 가로 넘침과 브라우저 오류는 없었다.
  - 이때 고친 화면 문제: 목업 배송일이 지난 날짜(9/17)로 보이던 것을 발표 당일 기준 "내일 도착"으로, 품절 안내의 "○○을 제외하고"를 상품명 받침과 상관없는 "○○만 빼고"로 바꿨다.

## 실서비스 전환 점검

- 실제 BE로 시연할 때는 `.env.development.local`에 `GATEWAY_SERVICE_URL`과 팀 서버 인증 정보를 넣는다(README "팀 BE 서버에 붙이기"). 예전 설정의 `AGENT_SERVICE_URL`·`CATALOG_SERVICE_URL`·`ORDER_SERVICE_URL`만 있으면 로컬 기본 주소(`127.0.0.1:8080`)로 간다.
- FE Gateway PR #27과 BE Gateway PR #45의 피부 분석 경로가 반영된 버전에서 개발 프록시를 확인한다.
- BE 옵션 조회와 주문 `requestId` 멱등 처리 완료 후, 실제 재고 차감·409 품절·대안 재검색을 별도로 검증한다.
- 팀 서버의 유효한 인증 정보와 LLM 설정을 확보한 뒤 추천 이유, 리뷰 근거, 검색 품질을 확인한다. 현재 목업 시연은 이 검증을 대신하지 않는다.
